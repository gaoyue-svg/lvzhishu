# 测试方案

## 1. 测试目标

- 保证业务接口稳定
- 保证文件解析和向量化链路可回归
- 保证 RAG 回答有引用、少幻觉
- 保证 Agent 工作流可执行
- 保证后台配置不会破坏线上问答

## 2. 单元测试

覆盖范围：

- 参数校验
- Service 业务逻辑
- DAO 查询
- Chunk 切分
- Query Rewrite
- Citation Validator
- Prompt 渲染

## 3. 接口测试

覆盖核心 API：

- 用户登录
- 知识库 CRUD
- 文件上传
- 文档解析
- Chunk 查询
- Embedding 重建
- Chat
- Agent 调用
- Prompt 发布与回滚

## 4. RAG 测试

建立黄金问答集：

| 字段 | 说明 |
| --- | --- |
| question | 问题 |
| expected_law | 期望法律 |
| expected_article | 期望条款 |
| expected_answer | 参考答案 |
| difficulty | 难度 |

评估指标：

- Recall@K
- MRR
- NDCG
- Answer Relevancy
- Faithfulness
- Citation Accuracy

## 5. Agent 测试

测试场景：

- 法律咨询能否正确路由
- 合同审查能否识别高风险条款
- 案例分析能否返回相似案例
- 文书生成是否包含必要结构
- 工具调用失败时是否有降级回答

## 6. 前端测试

覆盖：

- 登录流程
- 表格筛选和分页
- 文件上传进度
- 聊天流式输出
- 引用展开
- Prompt 编辑
- Retrieval Lab 调试链路展示

## 7. 性能测试

关键指标：

- 单次 RAG 问答耗时
- Milvus TopK 查询耗时
- Rerank 耗时
- 文档解析吞吐
- Embedding 任务吞吐
- 并发聊天请求数

## 8. 安全测试

- 越权访问
- 多租户数据隔离
- 文件上传类型校验
- Prompt 注入
- 敏感信息泄露
- API 限流

## 9. 回归测试

以下改动必须触发回归：

- Prompt 修改
- Embedding 模型切换
- Chunk 策略修改
- Rerank 模型修改
- Agent 状态图修改
- Citation Validator 规则修改
