# 开发规范

## 1. 后端目录规范

```text
app/
├── api/
├── core/
├── service/
├── dao/
├── entity/
├── dto/
├── vo/
├── config/
├── worker/
├── rag/
├── agent/
└── tests/
```

## 2. 分层职责

| 层 | 职责 |
| --- | --- |
| api | 路由、参数校验、响应封装 |
| service | 业务逻辑 |
| dao | 数据访问 |
| entity | 数据库实体 |
| dto | 入参对象 |
| vo | 出参对象 |
| rag | RAG Pipeline |
| agent | LangGraph Agent |
| worker | 异步任务 |

## 3. 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 4. 异常规范

统一使用业务异常：

```text
BusinessException
```

异常需要包含：

- code
- message
- detail
- trace_id

## 5. 日志规范

建议使用 loguru。

日志字段：

- trace_id
- user_id
- tenant_id
- module
- action
- latency
- error

## 6. 命名规范

- Python 文件：snake_case
- Python 类：PascalCase
- Python 函数：snake_case
- API 路径：kebab-case 或语义化资源路径
- 数据库表：snake_case
- 前端组件：PascalCase

## 7. Git 规范

提交类型：

- feat
- fix
- docs
- refactor
- test
- chore
- perf

示例：

```text
feat(rag): add hybrid retriever
fix(document): handle pdf parse failure
docs(api): add chat endpoint design
```

## 8. 配置规范

- 密钥不得写入代码仓库
- 本地配置使用 `.env`
- 生产配置通过环境变量或密钥管理服务注入
- 模型、Prompt、Agent 配置尽量入库管理

## 9. RAG 开发规范

- 每次检索必须记录 trace_id
- 每个回答必须保留引用来源
- Prompt 必须版本化
- Embedding 模型变更必须新建索引版本
- 检索调优必须保留评估集结果
