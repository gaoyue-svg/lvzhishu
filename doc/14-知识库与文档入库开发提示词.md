## 各文件详细要求

### 1. storage/oss.py — 阿里云 OSS 封装

不要引入第三方 OSS SDK（避免额外依赖），用 **HTTP 签名方式**直接调用 OSS REST API，或用 `oss2` SDK（如已安装）。

```python
class OSSClient:
    """阿里云 OSS 客户端"""

    def __init__(self, endpoint: str, access_key_id: str, access_key_secret: str):
        """
        endpoint: https://oss-cn-hangzhou.aliyuncs.com
        """

    async def generate_upload_url(
        self, bucket: str, key: str, expire_seconds: int = 3600
    ) -> str:
        """生成 STS 临时上传 URL（预签名 PUT），前端可直接用此 URL 直传 OSS"""

    def generate_download_url(
        self, bucket: str, key: str, expire_seconds: int = 3600
    ) -> str:
        """生成预签名下载 URL，用于私有文件临时访问"""

    def build_public_url(self, bucket: str, key: str) -> str:
        """构建公共读 URL: https://{bucket}.{endpoint}/{key}"""
```

要求：
- 使用 HMAC-SHA1 签名，兼容 OSS Authorization Header 格式
- `generate_upload_url` 生成的 URL，前端可以直接 PUT 文件上去
- 所有方法必须无阻塞（async 或轻量同步可接受，OSS SDK 的同步方法在 threadpool 中跑）

### 2. worker/task_queue.py — Redis Stream 任务队列

```python
# Stream Key 命名
DOCUMENT_PARSE_STREAM = "lawrag:stream:document_parse"

class TaskQueue:
    """基于 Redis Stream 的轻量任务队列"""

    def __init__(self, redis: Redis):
        ...

    async def enqueue(self, stream: str, task: dict) -> str:
        """入队一个任务，返回消息 ID"""

    async def consume(
        self, stream: str, group: str, consumer: str, block_ms: int = 5000
    ) -> list[tuple[str, dict]]:
        """消费任务，返回 [(msg_id, task_dict), ...]。
        使用 Redis Consumer Group 模式，支持多 Worker 并行消费"""

    async def ack(self, stream: str, group: str, msg_id: str) -> None:
        """确认任务完成"""
```

要求：
- 使用 `XADD` / `XREADGROUP` / `XACK` 命令
- Stream 不存在时自动创建
- Consumer Group 不存在时自动创建（`XGROUP CREATE ... MKSTREAM`）
- 消费时批量读取（`COUNT 5`），减少 Redis 往返

### 3. worker/parser.py — 文档解析 Worker

这是一个**独立进程**，不是 FastAPI 的一部分。启动方式：

```bash
uv run python -m backend.worker.parser
```

```python
# 启动时：
async def main():
    # 1. 连接 Redis
    # 2. 创建 TaskQueue
    # 3. 循环消费 lawrag:stream:document_parse
    # 4. 每取到一条任务：
    #    a. 从 OSS 下载文件到临时目录
    #    b. 根据 file_type 选择解析器：
    #       - .pdf  → pdfplumber 或 PyMuPDF
    #       - .docx → python-docx
    #       - .txt  → 直接读取
    #       - .html → beautifulsoup4 提取文本
    #    c. 文本清洗：去页眉页脚、合并空白行、统一换行
    #    d. 调用 services/parser.py 的 chunk_and_extract()
    #    e. 写入 knowledge_chunk 表（batch insert）
    #    f. 更新 knowledge_document 状态（parse_status → completed, chunk_count）
    #    g. 更新 knowledge_base 计数（doc_count, chunk_count, total_size）
    #    h. ACK 消息
    # 5. 异常处理：捕获异常 → 写入 error_message → 标记 parse_status=failed → ACK（避免死循环）
```

要求：
- 作为独立 `__main__` 模块运行
- 每次处理完一条消息立即 ACK，失败也 ACK（但写 error_message）
- 解析时打印进度日志（含 trace_id 风格的 document_id 标识）
- 支持优雅退出（SIGINT/SIGTERM → 完成当前任务后退出）

### 4. services/parser.py — 解析与 Chunk 切分

```python
async def parse_document(file_path: str, file_type: str) -> str:
    """解析文档，返回纯文本。
    - PDF: 用 pdfplumber 提取文本 + 表格
    - DOCX: 用 python-docx 提取段落
    - TXT: 直接读取
    """

async def chunk_document(
    text: str,
    kb_type: str,           # law / case / contract / enterprise
    chunk_size: int = 500,  # tokens（粗略按 1 token ≈ 2 字符估算）
    chunk_overlap: int = 50
) -> list[dict]:
    """
    切分文本为 Chunk 列表，返回值:
    [
      {
        "chunk_index": 0,
        "chunk_type": "paragraph",  # article(法条级) / paragraph(段落级)
        "text": "...",
        "token_count": 120,
        "metadata": { ... }
      },
      ...
    ]
    """

async def extract_metadata(
    text: str, kb_type: str, filename: str
) -> dict:
    """
    从文本中提取法律元数据，放在 knowledge_chunk.metadata JSON 中。

    根据 kb_type 策略不同:

    - kb_type=law（法条）:
        正则匹配提取: law_name（从文件名或文本标题）、article（条号）、
        chapter（章节名）、effective_date、keywords

    - kb_type=case（案例）:
        正则匹配提取: case_name、case_no、court、cause_of_action、
        judgment_date、plaintiff、defendant

    - kb_type=contract（合同）:
        提取: contract_name、clause_title、clause_type、party

    - kb_type=enterprise / judicial:
        通用提取: 标题、关键词、来源页码
    """
```

Chunk 切分策略（法律特化——本阶段核心）：

```
1. 先尝试按法条结构切分（正则匹配"第X条"、"第X款"等标记）
   → 命中: chunk_type = "article"，一条法条 = 一个 Chunk
   → 未命中: 回退到段落级切分

2. 段落级切分:
   - 按 \n\n 分段落
   - 合并短段落直到接近 chunk_size
   - chunk_overlap: 相邻 Chunk 之间重叠 50 tokens 的文本

3. 每条 Chunk 的 metadata 中包含:
   - 从 extract_metadata() 提取的结构化信息
   - source_file: 原始文件名
   - chunk_index / total_chunks
```

async def upload_document(

## 质量标准

- 所有文件上传走流式处理，不在内存中缓冲大文件
- OSS Key 严格遵循命名规范：`{user_id}/{kb_id}/{document_id}/{filename}`
- PDF 解析失败时，错误信息写到 `knowledge_document.error_message` 中
- Chunk 切分的 metadata 中必须包含足够的法律检索字段（法条号/案由等）
- Worker 崩溃后重启不丢任务（Redis Stream Consumer Group 自动从 pending 恢复）
- 删除知识库时，OSS 文件不物理删除（标记清理，后续定时任务统一处理）
- 所有接口返回统一 `ApiResponse` 格式
- 所有数据库操作使用 async session
