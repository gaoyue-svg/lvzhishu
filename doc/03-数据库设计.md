# 数据库设计

## 0. 数据库选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 关系型数据库 | MySQL 8.0+ | 业务主库，InnoDB 引擎，utf8mb4 字符集 |
| 缓存 | Redis 7+ | 会话缓存、短期记忆、任务状态 |
| 对象存储 | 阿里云 OSS | 原始文件、解析结果、导出报告 |
| 向量数据库 | Milvus | 向量检索，按知识库类型分 Collection |
| 图数据库 | Neo4j（后续） | 法律知识图谱 |

法律数据（民法典、判例、合同模板）与普通文档一视同仁，统一走 **用户上传 → 知识库 → 文档 → Chunk** 这条链路，法律特化字段通过 `knowledge_chunk.metadata` JSON 存储。

## 3. 知识库模块

### 3.1 knowledge_base

每个用户可创建多个知识库，每个知识库关联一组文档。

```sql
CREATE TABLE `knowledge_base` (
    `id`            BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '知识库ID',
    `user_id`       BIGINT       NOT NULL                 COMMENT '所属用户ID',
    `name`          VARCHAR(100) NOT NULL                 COMMENT '知识库名称',
    `description`   TEXT         DEFAULT NULL             COMMENT '描述',
    `kb_type`       VARCHAR(30)  NOT NULL                 COMMENT '类型: law / case / judicial / contract / enterprise',
    `embedding_model` VARCHAR(100) DEFAULT 'bge-large-zh-v1.5' COMMENT '绑定的Embedding模型',
    `rerank_model`  VARCHAR(100) DEFAULT NULL             COMMENT '绑定的Rerank模型',
    `chunk_size`    INT          NOT NULL DEFAULT 500     COMMENT 'Chunk大小(tokens)',
    `chunk_overlap` INT          NOT NULL DEFAULT 50      COMMENT 'Chunk重叠(tokens)',
    `doc_count`     INT          NOT NULL DEFAULT 0       COMMENT '文档数量(冗余计数)',
    `chunk_count`   INT          NOT NULL DEFAULT 0       COMMENT 'Chunk数量(冗余计数)',
    `total_size`    BIGINT       NOT NULL DEFAULT 0       COMMENT '总文件大小(字节)',
    `status`        VARCHAR(20)  NOT NULL DEFAULT 'enabled' COMMENT '状态: enabled / disabled',
    `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_kb_type` (`kb_type`),
    KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库表';
```

### 3.2 knowledge_document

文件上传后存入阿里云 OSS，表中记录 OSS 路径及处理状态。

```sql
CREATE TABLE `knowledge_document` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '文档ID',
    `kb_id`           BIGINT       NOT NULL                 COMMENT '所属知识库ID',
    `user_id`         BIGINT       NOT NULL                 COMMENT '上传用户ID',
    `filename`        VARCHAR(255) NOT NULL                 COMMENT '原始文件名',
    `file_type`       VARCHAR(20)  NOT NULL                 COMMENT '文件类型: pdf / docx / xlsx / txt / image / html',
    `file_size`       BIGINT       NOT NULL DEFAULT 0       COMMENT '文件大小(字节)',
    `file_hash`       VARCHAR(64)  NOT NULL                 COMMENT 'SHA256摘要，用于去重',
    `oss_bucket`      VARCHAR(100) NOT NULL                 COMMENT 'OSS Bucket名称',
    `oss_key`         VARCHAR(500) NOT NULL                 COMMENT 'OSS对象Key（存储路径）',
    `oss_url`         VARCHAR(500) NOT NULL                 COMMENT 'OSS访问URL',
    `parse_status`    VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT '解析状态: pending / parsing / completed / failed',
    `embedding_status` VARCHAR(20) NOT NULL DEFAULT 'pending' COMMENT '向量化状态: pending / processing / completed / failed',
    `error_message`   TEXT         DEFAULT NULL             COMMENT '失败原因',
    `chunk_count`     INT          NOT NULL DEFAULT 0       COMMENT 'Chunk数量',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '上传时间',
    `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_kb_id` (`kb_id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_parse_status` (`parse_status`),
    KEY `idx_file_hash` (`file_hash`),
    UNIQUE KEY `uk_oss_key` (`oss_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库文档表';
```

### 3.3 knowledge_chunk

文档解析后切分为 Chunk，一条记录对应一个 Chunk。向量数据存入 Milvus，这里记录元数据。

```sql
CREATE TABLE `knowledge_chunk` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT  COMMENT 'Chunk ID',
    `document_id`    BIGINT       NOT NULL                 COMMENT '所属文档ID',
    `kb_id`          BIGINT       NOT NULL                 COMMENT '所属知识库ID',
    `chunk_index`    INT          NOT NULL                 COMMENT 'Chunk序号(从0开始)',
    `chunk_type`     VARCHAR(30)  NOT NULL DEFAULT 'paragraph' COMMENT '切分粒度: article / paragraph',
    `text`           MEDIUMTEXT   NOT NULL                 COMMENT 'Chunk原文',
    `token_count`    INT          NOT NULL DEFAULT 0       COMMENT 'Token数量',
    `vector_id`      VARCHAR(100) DEFAULT NULL             COMMENT 'Milvus向量ID',
    `metadata`       JSON         DEFAULT NULL             COMMENT '扩展元数据',
    `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`id`),
    KEY `idx_document_id` (`document_id`),
    KEY `idx_kb_id` (`kb_id`),
    KEY `idx_vector_id` (`vector_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库Chunk表';
```

## 7. 阿里云 OSS 存储规范

### 7.1 Bucket 规划

| Bucket | 用途 | 生命周期 |
|--------|------|---------|
| `lawrag-documents` | 用户上传的原始文档 | 永久保存 |
| `lawrag-parsed` | 解析后的中间结果（JSON/Markdown） | 30天自动删除 |
| `lawrag-reports` | 导出的审查报告、文书 | 永久保存 |
| `lawrag-avatars` | 用户头像 | 永久保存 |

### 7.2 OSS Key 命名规范

```text
# 原始文档
{user_id}/{kb_id}/{document_id}/{filename}
示例: 1001/2001/30001/民法典逐条解析.pdf

# 解析结果
{user_id}/{kb_id}/{document_id}/parsed.json
示例: 1001/2001/30001/parsed.json

# 导出报告
{user_id}/reports/{report_id}/{filename}
示例: 1001/reports/5001/合同审查报告-IT服务合同.pdf

# 用户头像
avatars/{user_id}/{filename}
示例: avatars/1001/avatar.jpg
```

### 7.3 OSS 访问控制

- 文档文件：**私有读写**，通过后端签发 STS 临时 Token 实现安全上传
- 报告文件：**私有读**，后端生成带签名的临时下载 URL（有效期 1 小时）
- 头像：**公共读**，直接通过 CDN 加速域名访问

## 8. Milvus Collection 映射

MySQL 中的 `knowledge_chunk` 与 Milvus 中的向量记录通过 `vector_id` 关联。

| Collection | 数据来源 | 说明 |
|------------|---------|------|
| `law` | 公共法律库的 Chunk，`kb_type=law` | 所有用户共享 |
| `judicial` | 司法解释的 Chunk，`kb_type=judicial` | 所有用户共享 |
| `case` | 案例库的 Chunk，`kb_type=case` | 支持公开案例+用户私有案例 |
| `contract` | 用户上传的合同，`kb_type=contract` | 用户隔离 |
| `enterprise` | 用户上传的企业制度，`kb_type=enterprise` | 用户隔离 |

检索时根据用户 ID 和知识库 ID 自动过滤可见范围。

## 9. 索引策略总结

```text
高频查询场景                      使用的索引
──────────────────────────────────────────────────
用户登录                         uk_username, uk_email
查看我的知识库列表                idx_user_id (knowledge_base)
查看知识库下的文档                idx_kb_id (knowledge_document)
最近会话列表                     idx_user_id + idx_updated_at (conversation)
查看会话消息                     idx_conversation_id + idx_created_at (message)
解析状态轮询                     idx_parse_status (knowledge_document)
检索Trace查询                   uk_trace_id (rag_trace)
审计日志查询                     idx_user_id + idx_created_at (audit_log)
```

## 10. 完整建表顺序

```text
 1. user
 2. knowledge_base          (FK → user)
 3. knowledge_document      (FK → knowledge_base, user)
 4. knowledge_chunk         (FK → knowledge_document, knowledge_base)
```
